# Сервис аутентификации для тестового задания Innotech

Регистрация, подтверждение email
Стек: FastAPI + SQLAlchemy + Alembic, PostgreSQL
Сам сервис, postgres и mailpit поднимаются через docker compose

## Запуск

```bash
cp .env.template .env # как минимум заменить JWT__SECRET
docker compose up --build
```

Миграции накатывает сервис `migrator` перед стартом приложения
Автодокументация на http://localhost:8000/docs, письма смотреть на Mailpit на http://localhost:8025

Как проверить сценарий: зарегистрироваться через `POST /api/auth/register`,
открыть письмо в Mailpit, перейти по ссылке (аккаунт активируется, на руки
выдаётся access token, из требований условия)
Роут `POST /api/auth/login` отдельно реализован, принимает email и пароль из регистрации

## Известные ограничения

Сделано осознанно, под объём и условие задания:

- Повторная отправка письма подтверждения не реализована, токен живёт 24 часа; повторная регистрация занятого email вернёт 409. При потерянном письме активировать аккаунт придётся руками через БД;
- Переход по ссылке подтверждения **не идемпотентен**. Повторный переход по ссылке выдаст ошибку;
- refresh токенов нет, после истечения access token нужен повторный логин;
- Регистр email не нормализуется: Alice@example.com и alice@example.com считаются двумя разными почтами;
- access token не привязан к БД, используется стратегия jwt.
